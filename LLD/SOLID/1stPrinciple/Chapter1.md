# Introduction to SOLID Design Principles


## Why the SOLID principle is Important?
Software is always in a state of flux. Each change in the software system can have a ripple effect, much like throwing a pebble into water. The SOLID principles help in minimizing these ripples and prevent destructive changes to the interface. They decrease the chance of unintended consequences when changes are made.


IN OOP 
- Classes can confine the ripples of change.
- Classes allow for the separation of concerns, such as choices in algorithms and data structures, or handling OS specifics.

The SOLID principles help to design our projects in a structured way, minimizing the impact of changes and making the codebase more maintainable.

1. Interface Segregation Principle (ISP)
2. Liskov Substitution Principle (LSP)
3. Open/Closed Principle
4. Dependency Inversion Principle
5. Single Responsibility Principle (SRP)(summary of all 4)
